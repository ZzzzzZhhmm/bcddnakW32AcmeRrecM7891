# 后续新训练快照保留策略提案

状态：仅提案，尚未授权执行任何删除。继续现有可恢复冷存，不因等待决定而停掉训练。此策略不改变数据、模型、12k预算、学习率、样本或最终checkpoint选择。

本轮已生成且受保护的step2与step66各约38.5GB完整恢复包。未来每256步左右保留一个完整操作性快照，整个12k过程可能产生约48份；全部双完整副本将超过现有本机可用空间。原稿数据、原specialist所有权重、全部现有CAS/raw、失败/unknown以及当前训练所依赖的父状态继续保护；它们不属于本提案的删除范围。

| 对象 | 建议处理 |
|---|---|
| 原稿/原训练资产、现有原件、CAS、失败/unknown | 不改动 |
| 首次正式step2、首次已验证续跑step66 | 永久保留完整状态；若冷存仍须两份完整副本及可恢复指针 |
| 固定里程碑3000、6000、9000、12000 | 永久保留完整模型、优化器、scheduler、RNG、游标与训练收据 |
| 最近两份完整操作性快照及活动任务的父状态 | 保留，禁止删除 |
| 后续新生成、从未用于正式评测的更旧非里程碑快照 | 仅在后继完整快照已验真、实际成功恢复并继续更新后，才可列入删除候选 |

可删除候选只允许来自本次新campaign后续明确登记的run目录。例如未来`legacy_pb_pooled_s3407_formal_20261114_v4/training/checkpoints/{weights,state}/step_000256`，它在成为最新快照或活动父状态期间始终受保护。候选具体路径必须在实际产生后单独列清，验证解析后的绝对路径在登记run内，逐项记录size/SHA、后继checkpoint、实际载入收据、活动进程/FD检查和保留理由，再进行操作；不递归删除run根目录。

即使候选模型/优化器payload获准删除，它的配置、源代码身份、training attestation、完整文件清单/哈希、数据游标、训练日志、后继关系与删除收据仍永久保留。不能按成功率/损失优劣决定保留哪个step，不能删除任何已用于正式结果、机制对照或失败归因的原件。任何条件不明即保持原状。

若不同意此策略，所有新快照继续完整保留；后续改用更稀疏、事先固定的保存端点并继续无损冷存，以实际空间决定是否能启动。不会擅自执行不可逆清理。
