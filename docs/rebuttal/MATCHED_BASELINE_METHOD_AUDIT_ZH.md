# 共同骨干对照的方法边界与待补证据

2026-11-09，正式同预算策略性能比较尚未开始。此次核对使用原方法论文与作者项目页，不能把当前实验控制名称改成已复现的基线。

ReCAP将检索的状态与动作序列共同作为条件，使用检索动作加残差的参数化，并联合监督未来观测。当前action-conditioned prior保留检索动作和事实历史，但未把检索视觉序列交给生成器；因此它回答简化控制是否足够，尚未完整回答具名ReCAP的共同骨干比较。[原论文 §4](https://arxiv.org/html/2606.15631v1#S4)、[作者代码入口](https://github.com/jeongeun980906/ReCAP-Cosmos-Policy)。

WarmPrior-Past以同一episode的历史动作构造训练先验，初始历史不足时回到Gaussian；Preview还改变预测长度和预测复用方式。当前跨回合检索先验不是其复现。若做固定H32/prefix4的适配，必须明确历史窗口与执行前缀的差异，不能直接把原方法整块执行的设置搬来后称作等预算。[原论文 Algorithm 1 与 §3](https://arxiv.org/html/2605.13959v1#S3)、[作者项目页](https://sinnnj.github.io/WarmPrior/)。

当前已完成的100更新属于固定0.25、直接检索动作条件的独立控制；其检查点和optimizer已封存，不能替代任一具名方法的结果。主比较仍需固定3000更新以及与Full相同的数据、初始化、有效batch、scheduler、NFE、动作步数和测试种子。仅有训练更新或软件检查不能填入SR表。

正式回应BB-W2时应分开提供：当前受控简化实验的真实结果、具名方法的可核实实现映射、无法保持原设置的适配差异。尤其不能省略“检索视觉条件”这一信息访问差别。如果增加直接检索状态与动作的控制，须使用独立schema、事前固定配置并从共同release重新训练；不将现有100更新接到新增参数后冒充连续匹配训练。现阶段先完成正在运行的配对回合和固定机制source，不让未经实现的新对照占用GPU。

仍未完成的实质事项是：具名方法的共同骨干head-to-head，以及当前简化控制的3000更新性能。回复稿不得将这两项写成已解决。
