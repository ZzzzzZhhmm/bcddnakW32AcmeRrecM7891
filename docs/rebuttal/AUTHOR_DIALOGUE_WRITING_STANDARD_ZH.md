## 回复结构

1. 开场感谢该审稿人的具体投入，凝练复述其实际认可的1–2项优点，再说明将逐项回应。Hh4E只认可问题重要性及整体信息整合思路，不能扩写成认可性能或机制有效性。
2. 条目标题使用 `WX / QX — 审稿人原始问题简述`；X 保留原 review 的编号，相关 weakness/question 可合并，单独的条目只列真实存在的编号。标题概括审稿人的问题，不放我方立场、数据结论或宣传性答复，也不另编顺序取代原编号。
3. 每条回应在标题后另起段落，第一句话整句加粗，一句话直接给出我方立场与最终答复。随后按本条需要展开控制设计、关键表格、分母和统计口径、分析/理论说明以及实际修订；不机械给每条塞入全部类型材料。主体用 we/our 承担设计、解释、实验和修订责任，技术定义可用客观陈述，不机械给每句加 we。
4. 结尾以审稿人可核查的方式说明我们澄清了哪些歧义、补充了什么证据、改写了哪些位置。仅总结已经完成且在当前修订 LaTeX 中存在的改动；待完成实验不能出现在“已解决”清单中。
5. 公开回复保持为作者与该审稿人的交流，不出现面向AC/meta-review的宣传、录用目标或索分要求。只有确有严重偏见并另行决定申诉时，才准备独立说明。

## 按问题性质选择回应方式

- **结论有直接证据支持：** 先给结论，再给最贴近根源担忧的实验干预、量化差异与分析。明确对照保留了什么、改变了什么，避免用总榜领先替代机制证据。
- **定义、分母或推理关系需要澄清：** 温和解释评价对象、因果阶段或理论条件，帮助读者理解，不把评语归咎为审稿人错误。例如 proposal applicability、covered-pool accuracy 和最终 task SR 必须分别解释；必要时引用准确来源，不能用引用替代所需实验。
- **原稿表述确有模糊或疏漏：** 简洁承认需要更清楚地呈现，说明具体改法，并仅在对应内容已存在于当前修订工程时使用“we have clarified/added/revised”。实验缺口不能冒充已通过文字澄清解决的问题。

三种方式可在一条中组合，不在对外文本暴露内部分类。对更广对象/环境泛化、完整外部方法复现等额外实证请求，不改写成更容易回答的另一个问题。模板迁移时保留友好、理性、自信的语气，不复制其他审稿人的认可点、事实或未经核验的修订承诺。

## 论文修订方式

- 实验较弱：补充直接证据、完善协议与对照，再以证据巩固原核心观点。不能用更强措辞替代缺失实验，也不因单个开发失败轻率否定全部原稿结果。
- 表述或逻辑有硬伤：替换含混、因果越界或误导的表达，说明实际计算、监督目标、评价对象与适用范围。
- 删除：仅对确实错误且无法修复的内容作有依据处理；普通薄弱实验和不利结果不作隐藏或择优删除。
- 限制集中、精准说明；贡献段和结论正面组织已获证据支持的主张，避免反复追加无关否定。

## 双遍自审

第一遍读者视角：是否像友好而坚定的作者答复，是否正面回应每条问题，开场认可是否忠于review，结尾是否形成明确修订成果。

第二遍科学核心：数值、公式、分母、对照和结论范围是否保真；已知负/unknown是否保留；条件论证是否连同定性方向整段标待验证。即使预想数据理想，也不能据局部repair推导最终SR、据family排除认证真实技能缺失或据零/零推出非劣效。

自审记录具体修改及依据，不用代拟审稿分数证明写作成功。
