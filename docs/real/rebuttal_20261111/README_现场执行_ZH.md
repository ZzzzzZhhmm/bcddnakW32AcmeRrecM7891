# WARM rebuttal：作者独立真机补采执行包

目标是用可核查的长时程、历史依赖和跨场景结果回答审稿人，而不是仅增加展示视频。R2P与SOR沿用原论文任务和成功标准；新增批次独立报告，不回填或替换原稿20次结果。

## 一、建议本周完成的最小闭环

| 优先级 | 内容 | 工作量 | 能支持的论点 |
| --- | --- | --- | --- |
| P0，只有一个任务时先做 | SOR：Full与NoRecollection在20个同一reset场景上配对 | 40次自主rollout | 四阶段有序操控中，当前回合历史是否改善完整任务与顺序决策 |
| P0，推荐完整方案 | 再做R2P：同样20个reset、两种模式 | 再40次，总80次 | 历史依赖的收益能否同时体现在原始目的地记忆和先后顺序记忆 |
| P1，直接回应demo少/库紧凑 | 新增20条遥操作示范：R2P/SOR各10条，各8 train/2 dev；有余力可增至各20条 | 20条最低，40条加强 | 扩大独立示范及姿态/布局覆盖；事件数与示范数分别统计 |
| P1，扩大库后的验证 | 选一个任务，用冻结扩展bank评测同一20个reset；对照是本轮原bank Full的同20个reset | 再20次 | 固定checkpoint下，增加示范多样性是否保留或提升行为复用表现 |
| P2，时间允许时 | 在一个预先固定的困难/目标技能族排除bank上，Full与candidate-null各20次 | 再40次 | 不完整或不适用经验条件下的实际门控、决策和任务结果 |
| P2，回应移盘问题 | R2P在两档现场验证并冻结的盘中心平移量下，各20次Full；d0为事先登记的主批次Full参照或另采20次 | 再40次，或独立d0时60次 | 位移幅度—完整任务SR曲线；具体见TASK_CARD_MOVED_PLATE_ZH.md |

优先完成80次主对照。若只能采一个任务，交付SOR完整40次优于分散采集两个任务的少量成功片段。新增20条示范和扩库评测属于第二批，不能在第一批80次评测中途更新checkpoint、bank、归一化或控制器。

## 二、现场开始前要冻结什么

填写`RUN_MANIFEST.template.yaml`。稿件报告PiPER单臂、头部/腕部RGB、七维TCP状态、七维绝对关节/夹爪动作、H32；这些是论文记录，现场设备、标定、控制频率、模型checkpoint和实现仍须逐项确认。20Hz是原始示范采样配置，不能直接当作真实部署闭环频率。

至少记录：checkpoint文件与SHA256、完整配置/代码版本、原bank版本与清单SHA、训练/开发split、动作/状态单位及归一化、相机标定/分辨率、H/prefix/NFE/K、回合时间/步数上限、现场既有安全停止与动作限幅配置。使用原已验证平台与控制约束；本包不下发硬件运动命令。

两种主模式：

- `full`：原WARM，当前回合历史和原bank均按原实现读取。
- `no_recollection`：相同checkpoint、观测、语言、bank、K、采样与控制预算；屏蔽当前回合的历史观测、已执行动作摘要、历史派生查询、重复行为证据和continuity/thread信息，保留当前观测及外部经验。只把一个history tensor置零而仍保留其他历史通道，不能记作此对照。

现场先做只读/影子验证，保存实际mask、历史读取日志与输入字段。没有验证该消融时，可以另采Full SR，但不把另一模型、清空bank或重置整套控制器的结果命名为NoRecollection。保留执行队列/低层控制器必需状态，不通过修改标定或动作语义实现消融。

## 三、固定任务与reset安排

使用`scenario_schedule.csv`，共R2P/SOR各20个场景。每个场景两种模式各执行一次；场景间完全重置recollection，场景内按原任务连续完成所有阶段。

- 两种桌面外观各10个场景；统计时分层报告，每种外观只有10次，不能单独夸大泛化结论。
- R2P三块相同盘子的原始来源按7/7/6平衡。香蕉经过共同中转位置，回放历史后才知道原盘是哪一块。指令不能说出原盘编号或位置。
- SOR两种放置顺序各10次。相同几何组使用两种相反历史，最终物体位置与放置顺序独立；取回阶段的当前语言/图像不得再次给出放置顺序。
- 模式执行先后已交替平衡。为减少温度、照明、操作者和电量漂移，按场景交错Full/NoRecollection，不先跑完全部Full再跑全部消融。
- 严格按清单执行，不按成功/失败替换场景、追加“更好的一次”或重开已开始的回合。若现场布局无法实现，先在正式批次启动前修改并冻结整个清单，记录差异。

任务阶段、完整成功标准及历史泄漏检查见`TASK_CARDS_R2P_SOR_ZH.md`。

## 四、一次trial的采集流程

1. 核对case和模式；保存初态头/腕照片、物体/盘位置、checkpoint与bank身份；清空上一回合历史。用同一reset恢复配对模式。
2. 连续开启头/腕录制和时间戳日志，再开始自主执行。第一条自主策略命令标记trial开始。
3. 记录每个阶段实际开始/结束、每次操作对象与目标位置、请求的顺序及实际完成的顺序。R2P重点保存回盘决策前帧；SOR重点保存第一次/第二次取回决策前帧。
4. 整个trial按预定时间/步数上限执行；成功、超时、掉落、错盘、顺序错误、人工纠正/接管、启动后的安全停止均如实记入。完整自主成功要求无人工纠正。
5. 停止录制、填写`trial_results_template.csv`和`critical_decisions_template.csv`；保存原日志/视频SHA。失败回合保留同样完整的数据，不只保存成功。

正式开始前的传感器/加载错误另记工程失败；同一case是否重试须先确认尚未发出自主命令并留原记录。开始后的失败不“重试取最好”。日志或终态无法判断的回合先标unknown，不填0/1；补核前不报告完整20次SR。

## 五、必须交付的文件

- 填好的运行manifest、冻结scenario表、两模式配置与消融验证记录。
- 每次trial一行结果：完整任务0/1、阶段完成、目的地/顺序决策、超时、掉落、人工介入、耗时/命令数、实际checkpoint与bank身份。
- 全部连续头/腕视频与原始执行日志；关键决策点保存无损当前观测/proprio、当时完整语言输入和相关历史来源。
- 若有检索/门控日志：top-K event ID、来源任务/episode/phase、gate/有效source gate、选中项、候选conditioning mask与历史读取mask。没有这些日志时标未采集，不能推断gate可靠性。
- 独立媒体manifest：文件相对路径、字节数、SHA256。大视频保存在作者现场存储；先回传小表、日志和关键帧，不挤占当前近满AFS，不把媒体/结果提交Git。

视频可以使用采集系统原生编码；保留首次连续录制文件，后续剪辑另存。至少可对应到task/case/method；头/腕同步并保留时间戳，画面能看见所有阶段。导出匿名版本时去除人名、机构和可识别音轨，原件保留。展示片段按预定规则选取，例如每个条件首个成功和首个失败；SR使用全部trial，不能由所选demo估计。

## 六、额外遥操作示范怎么采

使用`teleop_demo_manifest_template.csv`。最低新增20条：每任务10条，8 train/2 dev；扩充至40条时每任务16 train/4 dev。若原25条split可用，计划总数分别为45条（36 train/9 dev）或65条（52 train/13 dev）；这些是采集目标，实际以完整文件计数。

跨初始盘、物体位置/朝向、抓取位姿、接收区位置、两种桌面和SOR顺序分层。不同camera clip、同一episode切出的多个event、同一视频重复裁切，均不能计作独立示范。开发和正式评测场景不能进入bank；新bank沿用checkpoint绑定的状态/动作语义及训练归一化，不中途重算统计量。新增数据若需要重新训练，作为另一研究单独记录，不能混入固定checkpoint的扩库对照。

## 七、SR与证据验收

主指标是完整任务成功数/N；每种模式每任务目标N=20，另报各阶段成功及历史决策正确率，并给出其真实分母。R2P没进入回盘、SOR未完成两次放置的trial仍在完整SR分母中，历史决策正确率只在实际到达相应决策的trial中计算。

报告配对Full-minus-NoRecollection差值、95%区间、两方向不一致计数和场景层次。相反历史共享同一几何组时，bootstrap按几何组重采样；不把视频帧、replan或同一trial的多个决策当独立样本。20次/模式属于小样本；不存在显著差异不能写成非劣效。对困难bank的“无相关技能”须依据预定task/phase适用性审计，单凭移除任务标签或gate为0不能认证。

预计工时使用现场实际测得的`trial平均时长+reset时长`乘trial数，再加标注/导出；先测2次工程回合估时，不将其混入正式SR。验收要求80个计划trial均有明确状态、全部已开始trial有原视频/日志、身份一致、无择优替换、统计数与逐次表一致。可先交SOR完整40次，R2P随后追加。
