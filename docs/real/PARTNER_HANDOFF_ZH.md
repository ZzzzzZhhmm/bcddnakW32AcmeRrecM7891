# WARM Piper 真机部署与实验协作说明

版本 1.0　2026 年 9 月 16 日　供真机合作方技术负责人及现场操作人员使用

我们希望用现有 Piper 桌面机械臂完成三个可重复的任务，验证机器人能否利用过去的观察和操作经验，作出正确的下一步选择。我们负责全部训练与模型交付；请贵方负责现场硬件、人工示范采集、本地推理及真机试验。第一步请回填第七部分的条件表，并提供设备照片和只读设备清单。现场条件确认后，双方再冻结采集接口和实验排期。

## 一 项目背景与目前进展

WARM 基于 FastWAM 开发。基础模型根据相机画面、机器人状态和任务指令，预测接下来一小段动作。我们的改进称为 retrospection，可理解为“结合刚才发生的事情，判断哪段过去经验现在值得用”。

例如，机器人把物体从左侧取到中央，使用后要放回左侧；下一次物体来自右侧，中央画面可能完全相同，正确的归还方向却不同。模型需要记住来源，还要判断经验库里“向左放”和“向右放”哪一个适用于这一次。旧动作会经过适配；经验库不等于固定动作脚本。

当前项目已有 LIBERO 仿真训练和评测路径，使用两路 RGB 图像、末端运动与夹爪动作。仓库结果文档记录如下；这些是仿真结果，不是 Piper 实测结果，也不是本合作的真机成功率承诺。

| 仿真套件 | 成功次数与评测次数 | 记录成功率 |
|---|---|---|
| Spatial 空间变化 | 492 / 500 | 98.4% |
| Object 物体变化 | 500 / 500 | 100.0% |
| Goal 目标变化 | 493 / 500 | 98.6% |
| Long 多阶段任务 | 489 / 500 | 97.8% |

## 三 首批三个桌面任务

三个任务都先用单臂完成，采用大而轻的物体、宽口托盘和清楚的视觉提示。相机视角、动作接口和数据记录可靠后再加复杂度。提示必须真的被模型看到；显示时长依据实测观察间隔确定。

### 任务一 取用后归还原位

设置两个或三个相同托盘，物体随机从一个托盘取到固定中央区，再归还来源托盘。归还前将物体、机械臂姿态和当前画面尽量对齐，使机器人需要依据此前看到的来源作选择。

要验证的是“记住来源并正确使用放置经验”。视频可并排展示中央画面近似相同、最终归还方向不同的两次试验。最低版本为两个托盘和一个物体；增强版本增加起点、物体实例和位置变化。成本低，主要道具为轻物体、托盘和定位垫。

采集需均衡覆盖各来源，避免原位留下只有一个托盘才有的痕迹。记录归还首次选择准确率、整任务成功率和完成时间。主要风险是固定顺序或当前图像泄露答案，以及抓取失败掩盖记忆能力。

### 任务二 短暂提示后的顺序触碰

两个或三个大触碰区按随机顺序逐次亮灯，随后熄灭；机械臂按看到的顺序触碰。每次触碰的确认灯短暂出现，之后复原。采用低作用力或非接触检测，避免把任务变成未经验证的力控操作。

要验证的是“记住多次提示及已完成步骤，避免重复或遗漏”。视频连续显示提示消失后仍正确执行。最低版本为两个触碰区及慢提示；增强版本为三项顺序、不同等待时间和位置。成本中等，需要触碰区、灯和简单记录控制器。

采集需覆盖不同顺序及间隔，保留全部提示阶段。记录完整顺序成功率、重复和遗漏次数。风险包括灯太小、提示漏采，以及屏幕持续显示顺序或计数形成旁路。成功判定程序可以知道答案，但不能把答案输入策略。

### 任务三 收到拒收反馈后改选

设置两个或三个浅托盘，每轮随机指定一个接收位。放入物体后用清楚的短暂灯光显示接受或拒收；拒收时机器人取回物体，改选其他位置，避免重试已拒收位置。托盘无需真实卡住物体。

要验证的是“利用已发生的反馈恢复任务，并避免错误复用旧经验”。视频展示尝试、拒收、取回和改选的完整过程。最低版本为两个托盘、一次拒收和一次恢复；增强版本增加第三托盘及不同初始尝试顺序。成本中等，需要托盘、反馈灯和可记录的检测方式。

示范应包含正确恢复后的成功轨迹，均衡覆盖目标和历史。记录限定尝试次数内成功率、重复访问拒收位的比例及恢复时间。风险是反馈没被看到、固定扫描顺序绕过记忆。这里验证任务级反馈恢复，不主张已解决任意机械接触故障。

## 四 扩展任务与正式实验

前三项稳定后，再根据时间选择下列扩展。扩展不是首轮交付的前置条件。

| 扩展任务 | 验证内容及视觉呈现 | 最小版本与增强方向 | 成本及主要风险 |
|---|---|---|---|
| 短暂订单后的多件装盘 | 提示撤去后完成多步订单，不漏放、不重复放；录像保留提示及完整执行 | 两种轻物体、两步订单；再增加三步、物体实例与背景变化 | 低至中；需订单分支示范和挡板。已完成物体一直可见可能绕过记忆；遮挡不能挡住安全操作 |
| 双臂经托盘接力 | 两臂在不同阶段利用历史正确交接，呈现完整多阶段协作 | 通过固定托盘依次放取；再增加位置和阶段变化 | 高；需要双臂动作接口、同步、碰撞控制和专门示范。必须重新适配模型，7 维单臂权重不能直接驱动两臂 |

扩展装盘记录订单完成率、漏放与重复率；双臂接力记录完整交接成功率、错阶段动作和总耗时。对照使用同样示范预算的基础模型、仅保留当前任务历史的版本和完整 WARM。双臂先用固定托盘，不采用空中递物。扩展数据与工时单独估计。

首轮开发试验建议三任务、三个模型版本、每组十次，共约 90 次，用于发现问题。正式实验候选方案为三任务、六个版本、每组至少三十次，共 540 次；我们提供版本和运行清单，贵方逐项执行。三十次是起步数量，不保证足够统计精度；最终数量依据 pilot 波动和双方预算冻结。

六个版本用于比较基础模型、仅当前任务历史、仅跨任务经验、完整方法，以及经验注入和后果判断的两个消融。各版本使用匹配的真实示范、训练和测试条件；由我们实现和训练，贵方不需改模型结构。模型若共享完整 WARM 预训练，报告会明确消融适用的训练阶段。

正式试验要求如下：

1. 固定测试布局和随机化方案，交错运行不同版本；每个任务分支均衡。开发数据用于调试，保留测试不进入训练和经验库。
2. 记录全部尝试，包括失败、超时、接管和安全停止。接管不计作自主成功；设备故障按预先约定规则单独标记，不能只保留成功录像。
3. 同时报整任务成功、关键选择准确率、重复尝试、耗时和安全干预。机械抓取失败与历史决策失败分开标注。
4. 由我们提供“相似但不适用的完整经验”干扰配置，贵方按清单复测。实验需同时展示正常经验收益与干扰下表现，才能支撑选择性使用经验的结论。
5. 留存同场景不同历史的配对试验，并检查答案未通过指令、文件名、时间表或额外状态泄露给策略。录像叠加答案仅用于事后展示。

若每次试验连同复位约 2–3 分钟，540 次约需 18–27 小时现场执行，尚不含布景、调试、采集及额外干扰实验。请贵方据实际复位速度回填工时，不把演示视频数量当作实验次数。

## 五 采集内容与双方数据交接

先采集任务一的五条完整样本供我们检查；通过后扩展到每任务约二十条 pilot，再按每任务五十条训练示范和十条独立开发示范起步。三个任务约一百八十条，pilot 可经质检后纳入训练，不必重复计数。正式测试独立安排，数量不包含在示范预算内。

| 必须保存的内容 | 用途与注意事项 |
|---|---|
| 两路原始 RGB 及时间戳 | 固定 external、wrist 顺序；保留清楚的提示与反馈，压缩方式双方确认 |
| 实测机器人状态 | 六关节角、工具位置与朝向、夹爪开度及各自时间戳；明确单位和坐标系 |
| 实际下发目标与反馈 | 记录目标位姿、夹爪目标、是否被控制接口接受及后续实测状态；目标不等于已达到 |
| 完整任务边界 | 提示开始、每一步操作、反馈、恢复、结束后的最终观察；N 个动作需有 N+1 个边界观察 |
| 标识和标定版本 | 任务、采集 session、episode、相机、工具和坐标定义；可追溯到当天现场配置 |
| 独立结果记录 | 成功、失败、接管、异常及录像；隐藏答案单独给评估器，不能当作策略输入 |

优先使用可以记录真实下发目标的遥操作。如果贵方采用关节主从或拖动示教，请先明确能导出哪些字段。只有被动位姿轨迹时，我们需要额外定义动作标签重建、轨迹处理和回放验证；请不要直接把相邻实测位置之差当作控制命令。

仓库提供的第一版数据格式只覆盖“单臂、两相机、笛卡尔目标命令”，不假装兼容所有示教设备。贵方可保留现有采集器，由小型适配层输出该格式；如果现有方案不能输出，先交付原始样本，双方调整格式后再批量采集。

采集到的停顿、丢帧、被拒绝命令和无恢复失败应保留原始诊断记录。不要通过补零、复制帧或删除失败片段掩盖问题。格式校验只检查记录关系，不能替代画面质量、实际标定和动作语义检查。前五条必须由双方共同看视频和数据。

贵方向我们提供原始数据、标定与采集说明；我们负责转换、训练集统计、真实经验库、微调和模型选择。开发中发现的失败可安排人工补采；正式保留测试不回流。需要使用原测试改进模型时，必须重新建立独立测试。

我们返回同一版本的模型权重、基础资产依赖、推理环境说明、任务表、真实数据统计、经验库、相机和控制约定、标定引用及运行配置。贵方在现场推理主机安装并验证。代码通过仓库同步，数据与模型通过双方约定的文件通道传输；不将原始视频、数据、权重或密钥提交到 Git。

## 六 简短操作步骤与阶段交付

1. **回填现场条件。** 贵方提交第七部分表格、桌面与相机安装照片，以及采集主机和推理主机的设备清单。我们确认单臂首轮路线、未满足项和双方负责人。
2. **先验证底层控制和采集。** 贵方确认急停、watchdog、限位、工具、坐标、夹爪和时间同步，完成经监督的低速人工示教。此时不要求预训练策略已经能自主完成任务。
3. **交付五条 pilot 样本。** 贵方按约定接口采集完整任务一，运行格式校验后上传；我们检查图像、时序、标签和历史完整性，书面确认是否可扩大采集。
4. **扩充示范并在我们这里微调。** 贵方采集三个任务并备份数据；我们划分数据、构建真实经验库、迁移权重和训练。期间贵方可完善任务道具与评价器。
5. **在贵方设备做离线推理。** 我们交付可加载的模型后端和版本包，贵方用录制数据测试输出和延迟，返回启动日志、GPU 显存及各阶段耗时。当前 mock 仅能验证接口，不能代替这一阶段。
6. **分级接入机器人。** 离线轨迹检查通过后，贵方依次执行无运动输出 dry-run、监督单步、低速小空间抓放、完整任务一，再扩展任务二和三。任一阶段失败先定位，不跨级运行。
7. **开发试验及补采。** 贵方按开发清单运行并返回全部结果，我们区分控制、感知、时序、数据覆盖和模型问题；必要时补采并发布新的完整版本。
8. **冻结后正式评测。** 双方固定测试规则和版本。贵方完成全部对照、干扰实验与连续录像；我们统计分析并确认是否需要补充预先规定的测试。

进入电机执行前，至少核验每轴方向、旋转约定、单位、夹爪开闭、关节及速度加速度限制、工作空间、全连杆碰撞、工具负载、通信超时和急停。Piper 的真实控制方式必须通过适配器连接，不能直接发送 LIBERO 的归一化动作。

必须实测相机停帧、状态反馈冻结、推理服务退出、断网、过期或乱序响应、异常数值与 IK 失败。发生这些情况时，应停止接受新动作并进入现场验证过的安全状态；不要自动继续旧动作段。仅写一个 enable_motion=false 标记不等于已经完成物理隔离。

每阶段交付都附上版本、操作人员、时间、日志和失败说明。现场人员对物理操作和停止负直接执行责任；我们提供模型和软件诊断。任何安全检查未通过时，该阶段暂停推进。论文内部的经验选择门控不承担硬件保护功能。

## 八 随附工具和当前交付边界

本次工具位于仓库 scripts/real 和 src/fastwam/real。它们独立于仿真训练主流程，不导入 Piper 驱动、不使能电机。使用 Python 3.10 或以上即可运行设备清单、格式检查及 mock 联调，无需先安装整个 CUDA 训练环境。

在仓库根目录执行以下命令，输出目录每轮使用新名称：

```bash
mkdir -p outputs/partner_round01
python scripts/real/collect_inventory.py \
  --output outputs/partner_round01/inventory.json
python scripts/real/make_mock_episode.py \
  outputs/partner_round01/mock_episode
python scripts/real/validate_episode.py \
  outputs/partner_round01/mock_episode --allow-synthetic
python scripts/real/replay_inference.py \
  outputs/partner_round01/mock_episode --mock \
  --output outputs/partner_round01/mock_shadow.json
```

| 已提供 | 能做什么 | 不能据此认定什么 |
|---|---|---|
| collect_inventory.py | 读取 GPU 依赖和系统设备信息，不导入机器人驱动 | 不证明硬件连接 正确标定或运动安全 |
| EpisodeWriter 和 validate_episode.py | 记录并检查真实采集器输出的单臂数据 | 不替代相机采集 SDK 驱动 图像解码检查或训练转换 |
| make_mock_episode.py | 生成明确标为 synthetic 的接口测试样本 | 不是真实示范 不可当作训练或实验结果 |
| replay_inference.py | mock 联调；或加载我们后续交付的可信后端处理录制数据 | 当前未附可用 WARM 真机后端 不执行机器人 不衡量闭环成功率 |

真实相机采集器、现场动作适配及安全执行进程由双方在回填接口后接入；真实模型后端、数据转换、训练配置和可运行模型包由我们补齐。实时 server/client 和全套硬件驱动尚未在本次工具中完成，不能把 mock 测试成功解释为可以直接自主运行。

详细字段、EpisodeWriter 接入示例、真实后端接口和分阶段验收见同目录 README.md。对方可立即完成条件回填、只读盘点、mock 联调及已有采集器字段映射；正式批量采集和电机执行必须分别通过前述接口与现场安全验收。
